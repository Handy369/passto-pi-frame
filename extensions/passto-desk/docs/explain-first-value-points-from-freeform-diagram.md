# passto-desk 迭代记录：无 skill 自由绘图样板的价值点与缺口

日期：2026-05-21
来源样本：`/Users/handy/dev/passto-ai/extensions/pi-subagent/pi-subagent-运作流程图.excalidraw`
目的：沉淀当前“无 skill 自由发挥”相对旧 passto-desk 产物的有效价值点，作为后续迭代 passto-desk 的设计输入。

---

## 1. 结论摘要

当前这张由 agent **不使用 passto-desk skill** 独立生成的 `pi-subagent` 运作流程图，虽然在 Excalidraw 机制利用上仍然比较原始，但在“**作为解释图**”这一目标下，已经明显优于之前偏结构化生成的 passto-desk 图。

核心结论不是“不要 skill”，而是：

> 现阶段 passto-desk 更擅长结构保真、可回读、可持续协作；
> 但在“首轮给人看的解释图”上，默认约束过强，抑制了 LLM 自然的讲解式构图能力。

因此后续 passto-desk 迭代，需要明确吸收本样本体现出的“解释图价值点”，同时修复当前自由绘图在 Excalidraw 机制使用上的粗糙实现。

---

## 2. 当前样本的高价值点（应进入 passto-desk 后续设计目标）

以下价值点，建议作为后续 passto-desk 的 **readability-first / explain-first 模式** 的显式目标。

### 2.1 阅读入口清晰

样本明显优于旧 skill 图的地方在于，它先回答了读者的三个问题：

- 这是什么图？
- 这张图主要在讲什么？
- 我应该从哪里开始看？

对应实现：
- 标题区
- 一句 summary
- 明确的开始节点

这类“阅读入口层”对解释图极其重要，应作为首轮默认能力保留，而不是可有可无。

### 2.2 主干叙事清楚

样本不是把模块并列堆出，而是围绕“运作流程”组织叙事主干：

- 调用 subagent
- 校验形态
- mode / guard / profile 解析
- spawn / fork 分流
- child runtime 执行
- progress 汇总
- contract 校验
- 结果回收与 render

这种“讲过程”的组织方式，比“讲结构列表”更适合解释型图。

### 2.3 节点角色分化明确

样本自然形成了不同视觉角色：

- 开始/结束
- 决策点
- 处理步骤
- 错误出口
- 补充说明区

这意味着 LLM 在不被过度结构约束时，会自然生成“角色分化”的图，而不是统一矩形平铺。

### 2.4 抽象层级合适

当前样本没有把源码函数级细节直接倾倒进图中，而是做了适度抽象：

- 保留真实工作机制
- 省略对首轮理解不必要的实现细节
- 优先让读者理解系统如何工作

这说明解释图模式下，应该优先追求“机制理解正确”，而非“实现细节穷举完整”。

### 2.5 对照价值高

该样本对于 passto-desk 的迭代有很高的 benchmark 价值，因为它已经证明：

- 去掉当前强结构约束后，LLM 会更倾向于生成面向人阅读的图
- 标题、摘要、开始节点、主干叙事、说明区这些解释图结构，会自然浮现
- 问题不在“LLM 不会画解释图”，而在“当前 skill 默认路径压制了解释图表达”

### 解释

- 但它还不是最终理想实现
- 它的优势主要在 **结构表达与阅读组织**，而不是 Excalidraw 机制层面的高质量实现

## 4. 当前样本的关键缺口：它是在“模拟视觉”，不是“利用 Excalidraw 机制”

这是当前最重要的批评点，也是后续 passto-desk 必须吸收的方向。

### 4.1 文字不是图形对象的属性关系，而是独立元素靠位置贴合

当前样本里：
- 框体是一个元素
- 文字是另一个元素
- 两者通过坐标位置“看起来在一起”

问题：
- 这只是视觉拟合，不是对象级绑定
- 缺少 container / bound text 关系
- 后续移动、缩放、自动调整时容易失去稳定关联

应改进为：
- 文字应尽量作为容器元素的绑定文本或稳定属性表达
- 不应长期依赖“手工摆坐标”来暗示文字属于哪个框

### 4.2 箭头是独立线段，不是连接对象间的结构性连线

当前样本里：
- 箭头是独立元素
- 没有可靠绑定到起点对象和终点对象
- 更像“画了一条看起来差不多的线”

问题：
- 不具备结构性连接语义
- 移动节点时，箭头不一定稳健跟随
- 无法充分利用 Excalidraw 的连接机制

应改进为：
- 箭头应绑定到起止对象
- 尽量使用对象的可连接锚点，而不是任意坐标点
- 让“关系”成为图元机制的一部分，而不是纯手工绘线

### 4.3 没有明确利用“对象可连接的固定点 / 边界锚点”

当前样本中，箭头连接点本质上还是人工估算位置。

问题：
- 这会让连线的视觉质量和稳定性都依赖坐标猜测
- 对复杂图尤其脆弱

后续应优先利用：
- Excalidraw 对容器/图形边界的连接能力
- 稳定的上/下/左/右侧锚点策略
- 根据阅读方向选择优先连接边

### 4.4 箭头说明文字不是箭头的属性，而是独立文字元素

当前样本中的 “是 / 否 / spawn / fork” 等标签，本质上仍然是单独 text 元素。

问题：
- 语义上属于 relation label
- 实现上却退化成“放在线旁边的一段字”
- 这同样是模拟视觉，而不是结构绑定

应改进为：
- relation label 应进入边的显式映射层
- 至少在中间结构中要知道“这段字属于哪条边”
- 视觉层应能稳定贴附到边，而不是游离成自由文字

### 4.5 目前是在模仿“看起来像图”，而不是建立“真正可编辑的图对象关系”

这是对当前样本最本质的总结：

> 它已经做到了逻辑结构清晰，
> 但表现方式仍然主要是“模拟视觉”，
> 而不是充分利用 Excalidraw 自带的对象、连接、绑定与可编辑机制。

这说明：
- “解释图能力”与“Excalidraw 机制正确使用”是两个维度
- 当前无 skill 样本证明了前者
- 后续 passto-desk 应该努力把两者结合起来

## 5. 对 passto-desk 的迭代启发

### 5.1 不要丢掉当前样本体现的解释图价值

passto-desk 迭代时，不能只回到“结构更强、回读更稳”的方向，而忽视当前样本已经展现出的解释图优势。

必须保留并制度化的能力：
- 标题区
- 摘要区
- 开始节点
- 主干叙事
- 角色分化
- 补充说明区（但需克制）
- 信息分层
- 面向人类理解的首屏阅读路径

### 5.2 需要把“解释图能力”与“Excalidraw 机制正确使用”合并

下一代 passto-desk 不应在以下两者之间二选一：

- 解释图更自然，但技术实现粗糙
- 结构映射更严谨，但图难看、难读

正确方向应该是：

> 既保留解释图的讲解式构图，
> 又用 Excalidraw 的对象/绑定/连接机制把它实现得更稳。

### 5.3 后续设计可以考虑显式拆为两层目标

#### 层 1：Explain-first diagram intent
关注：
- 给人看
- 首轮读懂
- 叙事主干
- 阅读入口
- 视觉主次

#### 层 2：Mechanism-correct Excalidraw realization
关注：
- bound text / container 关系
- 边绑定对象
- 稳定锚点
- relation label 归属
- 可移动可编辑不散架

也就是说：
- 图的“解释结构”先正确
- Excalidraw 的“机制实现”再正确
- 而不是只顾后一层，压垮前一层

## 6. 可直接转化为 passto-desk 需求的条目

以下条目可直接作为后续需求池：

### Explain-first 需求
- 首轮默认产出解释图，而不是结构全量图
- 默认包含标题、摘要、开始节点
- 默认优先主干流程，减少首轮横向扩张
- 决策、处理、异常、说明应有角色分化
- 允许隐藏次要关系，避免为了完整性牺牲可读性
- agent 画完图后，必须做一次基于提示词的自评，而不是画完即止

### Excalidraw realization 需求
- 文本与容器建立稳定绑定，不再仅靠坐标拟合
- 连线应绑定起止对象，而不是画自由箭头
- 连线尽量使用对象稳定锚点
- 关系标签应作为 relation/edge 的属性，而不是游离文字
- 元素移动后，文字与箭头应尽量保持语义关联不散架

### 策略需求
- 将“解释图生成”与“结构工作台生成”明确分为不同模式
- 首轮 explain-first，后续再增强结构可回读性
- 可读性评估不只看结构完整，还要看读者入口、主干与视觉负担
- 评分框架优先作为提示词工作流的一部分，而不是先做成脚本化检查器

## 7. 建议纳入 passto-desk 的“作图后自评提示词框架”

这个框架的目标不是让 agent 进行机械打分，而是：
- 强迫 agent 在“画完图之后”切换到审稿视角
- 用稳定维度复盘这张图是否真的适合作为解释图
- 在不依赖脚本的前提下，让提示词本身承担第一层质量门禁

### 7.1 使用时机

建议默认工作流变成：
1. agent 先完成 explain-first 图
2. agent 不立刻提交
3. agent 按以下评分框架自评
4. 若低于阈值，则先自我修图一轮
5. 再提交给用户或进入下一轮结构化增强

### 7.2 评分维度

建议至少固定以下五项，每项 1~10 分，并要求给出一句理由：

- 主干清晰度
- 阅读入口
- 视觉层级
- 版式节奏
- 信息取舍

可选第六项：
- Excalidraw 机制利用度

### 7.3 每个维度的判定提示

#### 主干清晰度
问自己：
- 用户是否能在几秒内看出这张图主要在讲哪条主流程？
- 主干是否被次要分支、注释、长文本冲淡？
- 是否存在必须来回扫视才能理解的路径？

#### 阅读入口
问自己：
- 图上是否清楚说明“这是什么图”？
- 是否有标题、摘要、开始点或明显起始入口？
- 第一次看图的人是否知道该从哪里开始读？

#### 视觉层级
问自己：
- 最重要的节点是否在尺寸、位置、颜色、样式上更突出？
- 决策、处理、异常、说明是否有角色区分？
- 是否存在所有东西看起来一样重的问题？

#### 版式节奏
问自己：
- 阅读路径是否顺滑，还是经常被迫大幅左右跳转？
- 节点之间是否过挤或过散？
- 分支与主干是否形成稳定节奏，而不是局部突兀鼓包？

#### 信息取舍
问自己：
- 是否只保留了首轮理解真正需要的信息？
- 是否把实现细节、边角说明、次要关系塞得过多？
- 这张图是在帮助理解，还是在焦虑式求全？

#### Excalidraw 机制利用度（可选）
问自己：
- 文字是否只是靠位置贴在框上，还是与主体形成稳定绑定？
- 箭头是否真正连接对象，而不是手工画线？
- 关系标签是否属于边，而不是漂浮文字？
- 移动元素后，图是否容易散架？

### 7.4 建议输出格式

建议 agent 在内部或显式输出如下结构：

```md
自评（解释图标准）
- 主干清晰度：8/10 —— 主线明确，但某些分支仍略抢戏
- 阅读入口：9/10 —— 标题、摘要、开始点都比较明确
- 视觉层级：7/10 —— 主次存在，但局部节点权重仍偏平均
- 版式节奏：6/10 —— 横向略长，阅读带不够稳定
- 信息取舍：7/10 —— 解释够用，但说明区略偏多
- Excalidraw 机制利用度：4/10 —— 仍偏模拟视觉，绑定与连接机制使用不足

是否需要自我修图：需要
优先修改项：
1. 收缩横向跨度
2. 降低次要分支权重
3. 提升对象绑定与连线机制正确性
```

### 7.5 建议阈值

对于首轮 explain-first 图，可采用如下软阈值：
- 主干清晰度 < 8：建议重做主干组织
- 阅读入口 < 8：必须补标题 / 摘要 / 开始入口
- 视觉层级 < 7：建议强化角色区分
- 版式节奏 < 7：建议重排布局
- 信息取舍 < 7：建议删减次要信息

如果加入第六项：
- Excalidraw 机制利用度 < 6：可允许先提交为解释图样板，但应记录为后续机制优化项

### 7.6 推荐给 agent 的提示词模板

可直接把下面这段作为 passto-desk explain-first 模式中的自评提示词：

> 你已经完成首轮解释图。现在不要立刻提交，先切换到审稿视角，按“解释图标准”自评这张图。请分别给出以下维度的 1~10 分与一句理由：主干清晰度、阅读入口、视觉层级、版式节奏、信息取舍。可选补充：Excalidraw 机制利用度。然后判断这张图是否需要先自我修订一轮；如果需要，请列出最多 3 个最优先修改项。评分标准不是工程回读完整性，而是“第一次看到这张图的人，能否快速理解主干，并愿意继续读下去”。

这个提示词的关键点是：
- 它评的是解释图，不是结构完备度
- 它鼓励 agent 自己发现“讲不清”“看不顺”“塞太多”的问题
- 它可以先作为纯提示词工作流落地，不依赖脚本

---

## 8. 当前结论一句话版本

> 当前无 skill 样本已经证明：LLM 本身能生成更强的解释图结构；
> passto-desk 后续不应压制这种能力，而应把这种“讲解式构图”保留下来，
> 再用 Excalidraw 的对象绑定、连线锚点、关系标签等机制，把它从“模拟视觉”升级成“机制正确的图”。
