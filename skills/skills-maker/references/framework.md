# Skills Maker Framework

## 唯一骨架

所有 Skill 共享唯一底层结构：

```text
Why → What → Structure → Flow → Surface → Runtime Proof
```

这是唯一骨架，不再额外引入“类型层”作为第二结构。

---

## 递归自相似公理

1. `skills-maker` 自己必须服从六段骨架
2. `skills-maker` 产出的每个具体 Skill，也必须服从同一骨架
3. 所谓“局部强化型 / 组合编排型 / 多输入同构型”，只是某个 Skill 在 `Flow` / `Surface` 上的表现形状，不是额外结构
4. 六段骨架写完后，还必须补足：
   - 边界包
   - 结构决策表
   - adopt / proof 判据

否则六段仍可能只是薄骨架。

## 六段最小定义

### Why
回答：为什么需要这个 Skill？

最少要写清：
- 它压缩什么不确定性
- 没有它时，agent 最容易发散到哪里
- 它提升的是什么：确定性 / 稳定性 / 可控性 / 价值

### What
回答：它负责什么？不负责什么？

最少要写清：
- 主目标
- 主输出物
- 不负责的相邻任务
- 即使命中也不扩做什么

### Structure
回答：它以什么文件面存在？

最少要写清：
- 是否只需 `SKILL.md`
- 是否需要 `references/`
- 是否需要模板 / 脚本 / checklist
- 每类文件为什么存在
- 哪些属于 runtime surface
- 哪些只是外部验证资产
- 哪些文件应明确不存在，避免空骨架膨胀

### Flow
回答：命中后如何推进？

最少要写清：
- 命中条件
- 首个读取点 / 首个动作
- 收敛与行动顺序
- handoff 规则
- 停止扩展条件
- 与相邻 Skill 的分流点

### Surface
回答：它如何被外化、读取、调用、复用？

最少要写清：
- 入口文件
- references 组织方式
- 输出载体
- 最小读取路径
- 是否需要多入口支持或总入口路由

### Runtime Proof
回答：如何证明它有效？

最少要写清：
- proof 类型
- 先验证什么
- 允许什么自然语言变体
- 不允许依赖什么窄字面量
- 如何判断 route 对了但 adopt 失败
- 外部验证资产是否需要独立存在

---

## 六段之外必须补的三件事

### 1. Boundary Pack
用于回答：
- 为什么该触发
- 为什么不该误吸相邻任务
- 命中后第一步是什么

### 2. Structure Decision Table
用于回答：
- 为什么这些文件要存在
- 为什么另一些文件不该存在
- 哪些是 runtime，哪些是 external

### 3. Adopt / Proof Contract
用于回答：
- 什么算真正进入该 Skill
- 什么算只是口头声称
- 修后如何验证不回退

## Flow / Surface 形状诊断

六段骨架成型后，再观察该 Skill 在 `Flow` / `Surface` 上更像哪种形状。

### 形状 1：局部强化型
对应过去常说的“原子 Skill”。

#### Flow 特征
- 局部、窄边界
- bounded work
- 单点不确定性压缩
- adopt 路径短

#### Surface 特征
- 文件面较小
- 入口较窄
- 输出合同较窄
- 常表现为单一方法块

### 形状 2：组合编排型
对应过去常说的“复合 Skill A”。

#### Flow 特征
- 总入口
- 子路径编排
- handoff 明显
- 通过多个方法块协同解决复杂目标

#### Surface 特征
- 常表现为 `router + references`
- 总入口 + 子路径材料
- 适合复杂目标整体编排

### 形状 3：多输入同构型
对应过去常说的“复合 Skill B”。

#### Flow 特征
- 输入类型多样
- 核心 workflow 高度一致
- 输出形状统一

#### Surface 特征
- 多输入入口
- 同一处理逻辑
- 统一输出合同
- 外化重点是输入覆盖，而不是子方法编排

## 常见错误

### 错误 1：先判型，后补骨架
错误。应先补完整六段，再做形状诊断。

### 错误 2：把形状当结构
错误。局部强化型 / 组合编排型 / 多输入同构型只是表现型，不是额外架构层。

### 错误 3：把 benchmark 当 Runtime Proof 的全部
错误。benchmark 只是 proof 之一。

### 错误 4：六段写全了，但边界和结构仍然过薄
错误。没有边界包与结构决策表，六段仍可能只是一层外观。

### 错误 5：把 runtime 与 external 资产混在一起
错误。会让 Skill surface 膨胀，也会让 agent 读取路径漂移。
